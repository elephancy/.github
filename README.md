# Shared repository checks

This public repository contains generic CI policy. It contains no deployment configuration, production credentials or private application source.

## Standard

| Tool | Applies to | Execution |
| --- | --- | --- |
| Semgrep Community Edition | Supported source languages | Pinned CLI and immutable upstream community security rules; no Semgrep cloud account |
| Trivy | Dependency manifests and infrastructure configuration | Pinned CLI, current vulnerability database, HIGH/CRITICAL findings fail |
| Gitleaks CLI | Every participating repository | Pinned open-source CLI, tracked Git history, fully redacted findings |
| GitHub native secret scanning | Repositories entitled by the existing GitHub plan | Enable scanning and push protection in repository settings |
| Codecov | Tests that generate real coverage | Upload a selected report using OIDC where permitted, or public tokenless uploads where the existing trust policy requires them |
| Lighthouse CI | Compatible web applications | Audit a local production build; keep reports as repository-scoped Actions artifacts |
| GameCI | Unity projects | Existing licensed engine gates, or an explicitly dispatched licensed build/test workflow |

Reusable workflows and third-party actions are pinned to commit IDs. Thin repository callers select the runner and applicable profiles. Changes to the shared policy are reviewed before callers advance their pinned revision.

Security jobs have read-only repository access, do not run application build/install hooks, and do not receive production secrets. Public and untrusted pull-request checks run on GitHub-hosted runners. Only repositories already enrolled in an isolated self-hosted pool may select that pool. The checks never mount a production Docker socket or access production paths.

Scanner failures and findings remain failures. Existing required checks and deployment gates remain authoritative; installing these checks does not silently replace them. Historical findings require specific, reviewed remediation or a documented narrow exception. Source snippets, discovered credential values and raw scanner output must not be published as public artifacts.

## Applicability and limits

- A README-only repository still benefits from secret scanning. Language-specific analysis and coverage become applicable when executable source/tests are added.
- Semgrep Community Edition supports a bounded set of languages and rules. Installing it is not proof of complete security analysis, especially for unsupported language features.
- Codecov processes coverage generated by tests; it does not run tests. Private uploads consume the account's existing plan allowance. Private cloud uploads need deliberate enablement after the account is connected; reports can still be retained in private Actions artifacts.
- GitHub Pro does not by itself enable native secret scanning for every private repository. Gitleaks remains the common secret-scanning baseline. No paid Secret Protection subscription is enabled by these workflows.
- Lighthouse reports use filesystem storage and Actions artifacts. Do not use temporary public storage for private projects. Authentication-dependent and backend-dependent routes need a suitable local fixture before auditing them.
- GameCI needs a valid Unity activation arrangement and sufficient compute/disk. Do not send Unity jobs to a constrained CI pool that has not passed a cold editor/import/test fit check. A manual workflow or installed Action is not proof of a successful licensed engine run.
- Archived repositories are not unarchived by rollout. Upstream forks retain their upstream workflow policy unless explicitly enrolled.

## Maintenance

Use the native dependency updater for action references. Keep scanner versions and download hashes together. Before advancing a shared policy revision, run its local fixture tests, workflow validation and a real Actions pilot. Record tool applicability and unresolved activation requirements in the repository's tooling configuration.
